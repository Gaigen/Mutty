# 🐸 Mutty — Голосовой/Видео чат с AI-ботом

**Mutty** — приложение для голосового и видеообщения в комнатах с AI-ботом, который умеет стримить музыку и видео из YouTube, SoundCloud, Twitch и других источников прямо в комнату.

Две платформы из одной кодовой базы:
- **Web** — React SPA, разворачивается через Docker (nginx)
- **Desktop** — Tauri 2 нативное приложение (Windows/macOS/Linux)

## 🏗️ Архитектура и связь модулей

```
┌─────────────────┐     POST /api/token      ┌─────────────────┐
│                  │ ───────────────────────>  │                  │
│   Frontend       │     {room, identity}      │   Token Server   │
│   (port 1420)    │ <─────────────────────── │   (port 4000)    │
│                  │     {token, wsUrl}        │                  │
└────────┬─────────┘                           └────────┬─────────┘
         │                                              │
         │  WebSocket (token auth)                      │ livekit-server-sdk
         │                                              │ (createDispatch)
         ▼                                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                                                                  │
│                    LiveKit Server (port 7880)                     │
│                    TCP/RTC (port 7881)                            │
│                    UDP/RTC (port 7882)                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
         ▲
         │  WebSocket (agent SDK)
         │
┌────────┴─────────┐
│                   │
│   Agent Server    │
│   (port 8081)     │
│   "youtube-bot"   │
│                   │
└───────────────────┘
```

### Поток данных

1. **Пользователь** открывает фронтенд → вводит имя комнаты, никнейм, выбирает аватар
2. **Frontend** делает `POST /api/token` к Token Server с `{room, identity, avatar}`
3. **Token Server** генерирует JWT через `livekit-server-sdk` → возвращает `{token, wsUrl}`
4. **Frontend** подключается по WebSocket к LiveKit Server по полученному `wsUrl` с `token`
5. Пользователь нажимает «Вызвать бота» → Frontend делает `POST /api/agent/dispatch`
6. **Token Server** через `AgentDispatchClient` отправляет запрос в LiveKit
7. **LiveKit** будит **Agent Server**, тот принимает dispatch и входит в комнату
8. **Agent** слушает чат-команды, стримит медиа через ffmpeg → публикует аудио/видео треки

## 🐳 Docker Compose — сервисы

### docker-compose.yml

| Сервис        | Образ / Билд         | Порт хоста → контейнера | Зависит от         |
|:--------------|:---------------------|:------------------------|:-------------------|
| `livekit`     | `livekit/livekit-server` | `7880:7880`, `7881:7881`, `7882:7882/udp` | — |
| `token-server`| `./backend`          | `4000:4000`             | `livekit` (healthy) |
| `agent-server`| `./agent-server`     | `8081:8081`             | `livekit` (healthy) |
| `frontend`    | `./frontend`         | `1420:80`               | `token-server` (healthy) |

### Сеть

Все сервисы в одной Docker-сети. Внутри контейнеров они обращаются друг к другу по именам сервисов:
- Token Server → LiveKit: `ws://livekit:7880`
- Agent Server → LiveKit: `ws://livekit:7880`
- Frontend знает только Token Server (адрес зашит при билде)

### Порты — что к чему

| Порт  | Протокол | Сервис       | Назначение                                    |
|:------|:---------|:-------------|:----------------------------------------------|
| 1420  | HTTP     | Frontend     | Веб-интерфейс (nginx → SPA)                  |
| 4000  | HTTP     | Token Server | REST API (токены, dispatch)                    |
| 7880  | WS/HTTP  | LiveKit      | WebSocket для клиентов + API                  |
| 7881  | TCP      | LiveKit      | WebRTC (TCP fallback)                          |
| 7882  | UDP      | LiveKit      | WebRTC (основной медиа-транспорт)             |
| 8081  | HTTP     | Agent Server | Внутренний порт агента (health/metrics)       |

## ⚙️ Переменные окружения

### .env (корень проекта — используется docker-compose)

```bash
# ═══════════════ LiveKit ═══════════════
LIVEKIT_API_KEY=devkey              # API ключ LiveKit (должен совпадать в livekit.yaml)
LIVEKIT_API_SECRET=secret           # API секрет LiveKit (должен совпадать в livekit.yaml)
LIVEKIT_WS_URL=ws://livekit:7880   # Внутренний URL LiveKit (docker-сеть)
LIVEKIT_PUBLIC_WS_URL=ws://localhost:7880  # Публичный URL (отдаётся браузеру)

# ═══════════════ Token Server ═══════════════
TOKEN_CORS_ORIGINS=*                # Разрешённые CORS origins (через запятую)
TOKEN_ROOM_MAX_LENGTH=100           # Макс. длина имени комнаты
TOKEN_IDENTITY_MAX_LENGTH=100       # Макс. длина никнейма
TOKEN_TTL=                          # Время жизни токена (по умолчанию LiveKit default)

# ═══════════════ Frontend (build-time) ═══════════════
VITE_TOKEN_ENDPOINT=http://localhost:4000/api/token  # URL токен-сервера для фронтенда

# ═══════════════ Agent Server ═══════════════
AGENT_MEDIA_PROXY=                  # HTTP/SOCKS5 прокси для yt-dlp/ffmpeg (опционально)
AGENT_VIDEO_FPS=30                  # FPS видео-стрима
AGENT_VIDEO_QUALITY=720p            # Качество: 360p / 480p / 720p / 1080p
AGENT_CHAT_TOPIC=lk-chat-topic     # Топик дата-канала для чата
```

### Переменные в деталях

#### LiveKit credentials
`LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` — единая пара ключей, которая должна совпадать:
- В `livekit.yaml` (конфиг сервера)
- В Token Server (для генерации JWT)
- В Agent Server (для подключения как агент)

#### Два URL LiveKit — зачем?
- `LIVEKIT_WS_URL` (`ws://livekit:7880`) — **внутренний**, используется Token Server и Agent Server внутри Docker-сети для общения с LiveKit
- `LIVEKIT_PUBLIC_WS_URL` (`ws://localhost:7880`) — **публичный**, возвращается браузеру в ответе `/api/token`. Браузер подключается по этому URL

В продакшене `LIVEKIT_PUBLIC_WS_URL` будет `wss://your-domain.com:7880` или через reverse proxy.

#### VITE_TOKEN_ENDPOINT
Зашивается в бандл фронтенда **на этапе билда** (Vite `import.meta.env`). В Dockerfile передаётся как `ARG`:
```dockerfile
ARG VITE_TOKEN_ENDPOINT=http://127.0.0.1:4000/api/token
```
Из него фронтенд также вычисляет dispatch endpoint: заменяя `/api/token` на `/api/agent/dispatch`.

#### AGENT_MEDIA_PROXY
Если YouTube/Twitch заблокированы на сервере, агент может использовать прокси:
```bash
AGENT_MEDIA_PROXY=socks5://proxy:1080
```
Прокси передаётся и в yt-dlp (для резолва URL), и в ffmpeg (для загрузки потока).

## 🔌 API — Token Server (port 4000)

### `GET /health`
```
→ 200 { "ok": true }
```
Используется Docker healthcheck.

### `POST /api/token`
Генерирует LiveKit JWT-токен для входа в комнату.

```json
// Request
{
  "room": "my-room",
  "identity": "Котик",
  "avatar": "frog"        // опционально
}

// Response 200
{
  "token": "eyJhbGciOi...",
  "wsUrl": "ws://localhost:7880"
}
```

**Валидация:**
- `room` и `identity` — обязательны, макс. длина настраивается, regex: `[a-zA-Z0-9_\-\u0400-\u04FF\s.]+` (латиница + кириллица)
- `avatar` — из списка: `bear, shark, hedgehog, otter, penguin, skunk, raccoon, capybara, frog, hamster, axsolotle, fox, monkey`

### `POST /api/agent/dispatch`
Вызывает бота в комнату.

```json
// Request
{ "room": "my-room" }

// Response 200
{ "status": "dispatched", "room": "my-room" }
```

Использует `AgentDispatchClient` из `livekit-server-sdk` для отправки dispatch-запроса.

## 🤖 Agent Server — возможности бота

Бот `youtube-bot` входит в комнату по dispatch-запросу и умеет:

### Воспроизведение медиа
- Стримит **аудио + видео** из URL прямо в комнату как LiveKit-треки
- Использует **yt-dlp** для резолва URL → **ffmpeg** для декодирования
- Поддерживает: YouTube, Twitch, SoundCloud, Telegram, и всё что поддерживает yt-dlp

### Качество видео
| Пресет | Разрешение | FPS |
|:-------|:-----------|:----|
| 360p   | 640×360    | 30  |
| 480p   | 854×480    | 30  |
| 720p   | 1280×720   | 30  |
| 1080p  | 1920×1080  | 30  |

### Чат-команды (Russian + English)
```
<url>                    — воспроизвести URL
add <url> / queue <url>  — добавить в очередь
skip / скип              — пропустить трек
queue / очередь          — показать очередь
clear / очистить         — очистить очередь
shuffle / перемешать     — перемешать очередь
stop / стоп              — остановить
аудио <url>              — только аудио
видео <url>              — аудио + видео
youtube <запрос>         — поиск на YouTube
soundcloud <запрос>      — поиск на SoundCloud
```

### Программные команды (JSON через data channel `agent-control`)
```json
{ "cmd": "mode", "mode": "audio" }       // переключить режим
{ "cmd": "quality", "quality": "1080p" }  // изменить качество
{ "cmd": "pause" }                        // пауза
{ "cmd": "resume" }                       // продолжить
{ "cmd": "repeat", "repeat": true }       // повтор трека
{ "cmd": "queue", "url": "..." }          // добавить в очередь
{ "cmd": "skip" }                         // пропустить
{ "cmd": "leave" }                        // бот покидает комнату
```

### Автоотключение
Бот автоматически покидает комнату, когда все остальные участники отключились.

## 🚀 Запуск проекта

### Предварительные требования
- Docker + Docker Compose
- Для desktop: Node.js 20+, Rust toolchain, Tauri 2 CLI

### 1. Быстрый старт (Docker)

```bash
# Клонируем
git clone https://github.com/Gaigen/Voice-app.git
cd Voice-app

# Копируем и настраиваем .env
cp .env.example .env
# Отредактируй .env при необходимости (см. раздел "Переменные окружения")

# Поднимаем всё
docker compose up --build -d
```

После запуска:
- **Фронтенд**: http://localhost:1420
- **Token Server API**: http://localhost:4000/health
- **LiveKit Dashboard**: подключение по ws://localhost:7880

### 2. Порядок запуска сервисов

Docker Compose поднимает сервисы с зависимостями:

```
livekit (7880, 7881, 7882)
    ↓ depends_on (healthy)
token-server (4000)          agent-server (8081)
    ↓ depends_on (healthy)
frontend (1420)
```

1. **LiveKit Server** стартует первым, ждёт healthcheck
2. **Token Server** и **Agent Server** стартуют параллельно после LiveKit
3. **Frontend** стартует последним после Token Server

### 3. Локальная разработка (без Docker)

```bash
# Терминал 1 — LiveKit (нужен бинарник livekit-server)
livekit-server --config livekit.yaml --dev

# Терминал 2 — Token Server
cd backend
npm install
cp ../.env.local.example .env  # или создай .env с нужными переменными
npx tsx server.ts

# Терминал 3 — Agent Server
cd agent-server
pip install -r requirements.txt
# Нужен ffmpeg в PATH
python main.py dev

# Терминал 4 — Frontend
cd frontend
npm install
echo "VITE_TOKEN_ENDPOINT=http://localhost:4000/api/token" > .env
npm run dev
```

### 4. Desktop-приложение (Mutty / Tauri)

```bash
cd mutty-app
npm install

# Dev mode
npm run tauri dev

# Сборка
npm run tauri build
```

Desktop-приложение не требует Docker — пользователь вводит URL сервера при первом запуске. Это может быть:
- Локальный `http://localhost:4000` (если бэкенд запущен локально)
- Удалённый сервер `https://your-server.com`

## 🔧 LiveKit конфигурация

### livekit.yaml (development)
```yaml
keys:
  devkey: secret            # Должны совпадать с LIVEKIT_API_KEY/SECRET
port: 7880
rtc:
  tcp_port: 7881
  port_range_start: 7882
  port_range_end: 7882
  use_external_ip: false
room:
  empty_timeout: 60         # Комната удаляется через 60 сек без участников
logging:
  level: info
```

### livekit-prod.yaml (production)
```yaml
# То же, но:
rtc:
  node_ip: 0.0.0.0         # Слушает на всех интерфейсах
  use_external_ip: true     # Определяет внешний IP автоматически
```

## 🔒 Безопасность

- **SSRF-защита в агенте**: блокирует `file://`, `localhost`, приватные IP, link-local адреса
- **Валидация ввода**: Token Server проверяет длину и формат room/identity через regex
- **CORS**: настраивается через `TOKEN_CORS_ORIGINS`
- **CSP в Desktop**: Tauri CSP разрешает `connect-src *` и `media-src *` (необходимо для LiveKit)
- **Nginx headers**: `X-Frame-Options DENY`, `X-Content-Type-Options nosniff`, `X-XSS-Protection`
